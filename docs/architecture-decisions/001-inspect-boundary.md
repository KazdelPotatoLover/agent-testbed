# ADR-001：M1 编排边界与 Inspect 复用

- 日期：2026-11-16
- 状态：M1 历史决策；M2 本地生命周期部分由 [ADR-004](<004-m2-local-worker-state.md>) 细化，Flow/BB 扩展点评估保留到真实接入前

## 背景与证据

[开发方案](<../development-plan.md>) 要求避免自造完整评测引擎。已核对锁定 Inspect 的 `eval` / `eval_set` 签名与官方 Eval Sets 页面。原生 Eval Sets 已提供批次重试、完成样本复用、继续运行；官方配套 Inspect Flow 已覆盖声明式配置、参数矩阵、日志索引和后处理。

来源：`https://inspect.aisi.org.uk/eval-sets.html`。本轮对 Flow 仅做文档和发行元数据核对，没有安装或实测，因此**不能断言 Flow 无法满足未来需求**。

## 决策

1. M1 使用最小的顺序矩阵展开；每个 attempt 调用一次真实 Inspect `eval`，不实现通用任务调度器。
2. Inspect 负责单样本执行、停止记录和原生日志；本项目负责公共任务数据、独立业务评分、冻结产物和实验级证据关联。
3. M1 不实现自动恢复、自动重试、多控制器或并发，也不同时套一层 `eval_set` 自动重试。进程中断记 incomplete，而非重新创建不确定工作。
4. 业务评分当前直接读取快照；原生 Inspect 重评分单独实测并保留后续集成路径。
5. 在 M2 开始建设持久化恢复前，必须用拟接入 BB 的幂等/取消及预算契约，继续评估 `eval_set`/Flow 扩展点；能复用则替换当前最小顺序循环，不因已有几十行循环就锁死架构。

## 当前没有证明的事

- Flow 是否能直接承载 BB 外部生命周期和跨角色准入。
- 任意 Agent 中间状态可恢复。
- 共享 Docker 或远程服务可以安全隔离。

下一决策必须给出针对这些边界的可执行证据，不能只因“需要控制”就重写已有能力。
